# Spark

Приложение для общения в локальной сети на Linux и Windows: текстовые каналы с историей, голосовые комнаты, видеозвонки, одновременная демонстрация экрана и камеры, передача файлов. Аккаунт и подключение к облаку для общения не нужны. Исходный код и выпуски доступны в [публичном репозитории Spark](https://github.com/EugeneHeisst/spark).

## Начать общение

1. Установите Spark на компьютеры одной сети. Для Windows используйте `Spark-…-windows-setup.exe` или распакуйте ZIP и запустите `Spark.exe`. На Linux откройте папку `Linux/Spark` из комплекта **Готовые файлы** и запустите `./spark` или `./spark-lan`. Сохраняйте всю папку целиком: рядом с бинарником находятся библиотеки, Rust-сервис и интерфейс.
2. На одном компьютере выберите **Создать комнату**, укажите своё имя, название комнаты и код минимум из шести символов. Компьютер создателя должен оставаться включённым.
3. На остальных выберите найденную комнату либо введите её адрес, показанный в боковой панели создателя, и тот же код. Например: `192.168.1.10:39393`.
4. Текстовые каналы работают сразу. Войдите в голосовой канал или пригласите участника кнопкой около его имени. Приглашение требует подтверждения перед включением микрофона.
5. Кнопки звонка управляют микрофоном, звуком, камерой и демонстрацией. Для демонстрации выберите отдельное окно или экран; камера может работать одновременно. Кнопка разворота на видео открывает крупный просмотр, а **На весь экран** — полноэкранный. Esc возвращает к чату, сохраняя звонок, камеру и демонстрацию.
6. Прикрепите файл кнопкой **+** около сообщения. Получатель самостоятельно выбирает место сохранения. Завершённая передача проверяется по SHA-256, максимальный размер файла — 2 ГиБ.

В **Настройках** можно изменить имя, выбрать тёмную, светлую тему или «Полночь», акцентный цвет, компактные сообщения и масштаб **75–150%**. Масштаб также меняется сочетаниями **Ctrl++ / Ctrl+-**, **Ctrl+0** возвращает 100%. Настройки сохраняются сразу и восстанавливаются при запуске.

Десять собственных звуков Spark обозначают подключение, выход, вход и выход других участников, новое сообщение, приглашение, включение и выключение микрофона и звука. В настройках доступны прослушивание, общая громкость и выключение звуковых уведомлений.

Во время звонка зелёная обводка отмечает активный микрофон: она появляется на аватаре, плитке камеры и карточке участника. Под видео доступны отдельные ползунки **Голос** и **Стрим** (0–100%) для каждого собеседника; значения сохраняются на вашем компьютере. Отключение звука звонка заглушает обе дорожки и сохраняет их уровни. В настройках **Голос и трансляция** можно переключить шумоподавление, в том числе во время разговора, без разрыва звонка. Эхоподавление остаётся включённым.

Для звонков с отдельным звуком трансляции обновите всех участников до версии 0.4.0 или новее.

По умолчанию закрытие окна скрывает Spark в трей: звонки продолжаются. Нажмите значок в трее, чтобы открыть окно, или выберите **Выйти из Spark** для полного завершения. Сворачивание в трей можно отключить в настройках. Если системный трей недоступен, закрытие завершает приложение.

История, каналы и отправленные файлы сохраняются на компьютере создателя комнаты между перезапусками. Имя и идентификатор клиента также сохраняются локально.

## Обновления

Spark получает обновления из стабильных [GitHub Releases](https://github.com/EugeneHeisst/spark/releases/latest). В настройках можно проверить наличие новой версии, скачать её и выполнить отдельную команду установки с перезапуском. Перед применением приложение проверяет размер и SHA-256 пакета по опубликованному `spark-update.json`. Автоматическая проверка и скачивание не завершают звонки: перезапуск запускаете вы, после завершения общения.

Linux-обновление заменяет распакованную папку приложения целиком, поэтому она должна быть доступна текущему пользователю для записи. На Windows используются ZIP для переносимой версии или установщик для установленной. Профиль, настройки и история хранятся отдельно от файлов приложения. До применения обновления можно продолжать пользоваться текущей версией.

## Сеть и разрешения

Spark использует TCP **39393** для комнаты, UDP **23994** для обнаружения и динамические UDP-порты WebRTC для прямых звонков. Разрешите приложение в брандмауэре **частной сети** на обоих компьютерах. Если обнаружение блокируется, подключайтесь по IP; если включена изоляция Wi-Fi-клиентов/гостевая сеть, прямое соединение может быть недоступно. Перенаправление портов на роутере для одной сети не требуется.

Звук демонстрации включается отдельно в окне выбора источника. Передаётся звук других приложений с исключением Spark; выбранное окно ограничивает только изображение. На Linux используются PipeWire и временный источник, на Windows — встроенное исключение собственного звука Chromium. При ошибке звукового захвата отключите передачу системного звука и выберите источник снова.

Используйте доверенную локальную сеть. Код ограничивает вход в комнату, но чат и файлы между клиентами и создателем передаются по HTTP/WebSocket без сквозного шифрования. Голос, камера и экран передаются напрямую через WebRTC с DTLS/SRTP. Нет STUN/TURN, облачного ретранслятора, телеметрии или автооткрытия полученных файлов. Для проверки и загрузки обновлений Spark обращается к GitHub по HTTPS; сообщения и файлы комнаты туда не передаются. Приложение и установщик пока без цифровой подписи; Windows может показывать SmartScreen.

## Архитектура

- `spark-service`: Rust, Tokio/Axum, SQLite, обнаружение, сообщения и потоковые файлы. Каждый клиент запускает отдельный сервис на случайном порту `127.0.0.1`; создатель дополнительно слушает порт комнаты в LAN.
- `spark-protocol`: общий типизированный протокол Rust.
- `spark-ui`: интерфейс и логика WebRTC на Rust/Leptos, компилируются в WebAssembly.
- `desktop/`: тонкая оболочка Electron с одинаковым Chromium на Linux и Windows, изолированным renderer, системным сохранением файлов и выбором источника экрана. JavaScript здесь отвечает за интеграцию с рабочим столом; приложение не является полностью нативным Rust-виджетом.

## Сборка из исходников

Нужны Rust stable (не старее 1.88), Node.js **24+**, npm и системные библиотеки Electron. На Ubuntu 24.04: `libgtk-3-0 libnss3 libasound2t64 libgbm1 libxss1 libxtst6`. На Windows используйте Rust MSVC и Visual Studio Build Tools с C++.

```sh
rustup target add wasm32-unknown-unknown
cargo install wasm-bindgen-cli --version 0.2.130 --locked
npm ci
npm run build
npm start
```

`npm ci` скачивает закреплённую версию Electron. `npm run build` собирает обе Rust-части и WebAssembly bindings. Упаковывайте приложение на соответствующей системе:

```sh
# Linux: распакованное приложение и TAR.GZ с папкой Spark/
npm run package:linux
# Windows: установщик и ZIP
npm run package:win
```

Результаты появляются в `dist/`. Для комплекта с обеими платформами скачайте проверенные Windows-артефакты CI в отдельный каталог и выполните на компьютере с готовой Linux-сборкой:

```sh
node scripts/collect-ready.mjs --windows-input artifacts/spark-Windows
```

Скрипт создаёт **Готовые файлы/Windows** с установщиком и ZIP и **Готовые файлы/Linux/Spark** с распакованным приложением, командами `spark` и `spark-lan`, всеми библиотеками и ресурсами. AppImage в комплект не входит. В корне находятся инструкция запуска и `SHA256SUMS.txt` для всех доставленных файлов. Если Windows-пакеты уже в `dist/`, аргумент можно опустить. `--linux-input` задаёт другой каталог распакованной Linux-сборки, `--output` — каталог результата; `--replace` разрешает заменить ранее созданный комплект.

Комплект создаётся только при наличии обеих платформ текущей версии из `package.json`. Скрипт проверяет версию внутри упакованных приложений, наличие Rust-сервиса, UI/WASM и звуков и не подбирает старые пакеты вместо отсутствующих. Он не собирает, не тестирует и не публикует приложение: перед сбором комплекта выполните проверки на обеих платформах.

Публикация стабильного релиза разрешена после успешных Linux- и Windows-проверок. CI выпускает три пакета текущей версии: `Spark-X.Y.Z-linux-x64.tar.gz` (папка `Spark/` с исполняемыми `spark` и `spark-lan`), `Spark-X.Y.Z-windows-setup.exe` и `Spark-X.Y.Z-windows-x64.zip`. `node scripts/update-manifest.mjs <каталог-пакетов>` создаёт `spark-update.json` и `SHA256SUMS` только при наличии всех трёх пакетов. Workflow сначала загружает их в черновик, сверяет опубликованные имена, размеры и SHA-256 скачанных файлов и затем публикует релиз. Для повторного использования проверенных CI-артефактов `publish-verified.yml` требует явные run ID, SHA исходников и тег; он сверяет успешные платформенные jobs и соответствие кода.

## Проверки

```sh
node --test tests/update/*.test.cjs
cargo test --locked -p spark-protocol -p spark-service
cargo check --locked -p spark-ui --target wasm32-unknown-unknown
# Linux: отдельный тестовый экран, реальные окна и отдельные Rust-сервисы
npm run test:e2e:linux
# Linux: реальный loopback тестового тона в отдельном PipeWire/Pulse-сервере
# Нужны pipewire, pipewire-pulse, wireplumber, pactl и paplay.
node scripts/test-loopback-linux.mjs
```

Тесты используют настоящие TCP/WebSocket-соединения, SQLite и файлы. Сквозной сценарий запускает два независимых приложения, отправляет сообщения в обе стороны, создаёт канал, сверяет полученный файл с исходными байтами, проверяет реальную передачу RTP, декодирование кадров обеих камер, mute/deafen, приглашение, завершение и повторный звонок, перезапуск процессов с сохранением истории.

В Linux дополнительно захватывается настоящее тестовое окно на отдельном Xvfb-дисплее и проверяются пиксели принятого видео. Исходный рабочий стол пользователя не захватывается. Только в распакованной сборке явный флаг `SPARK_E2E_MEDIA=1` включает синтетические микрофон/камеру; в упакованной версии он игнорируется. Снимки и реальные WebRTC-счётчики сохраняются в `test-results/`. Отдельный сценарий проверяет трёх участников и все шесть направлений передачи голоса, переход между голосовыми каналами и повторное подключение. Windows CI проверяет сборку, оба сетевых сценария и запуск упакованного приложения; захват экрана Windows и оборудование разных физических компьютеров требуют отдельной проверки.

Для демонстрации со звуком на Linux требуются PipeWire и утилиты `pw-loopback`, `pw-dump`, `pw-link`, `pactl`. Spark создаёт временный источник, который исключает собственное воспроизведение и удаляется после демонстрации. Уровни громкости и маршруты других приложений не меняются. Шумоподавление переключается кнопкой «Шумодав» рядом с микрофоном или в настройках голоса.
