# Spark

Приложение для общения в локальной сети на Linux и Windows: текстовые каналы с историей, голосовые комнаты, видеозвонки, одновременная демонстрация экрана и камеры, передача файлов. Аккаунт и подключение к облаку не нужны.

## Начать общение

1. Установите Spark на компьютеры одной сети. Для Windows используйте `Spark-…-windows-setup.exe` или распакуйте ZIP. На Linux запустите AppImage (`chmod +x Spark-*.AppImage`) либо распакуйте TAR.GZ и запустите `spark-lan`.
2. На одном компьютере выберите **Создать комнату**, укажите своё имя, название комнаты и код минимум из шести символов. Компьютер создателя должен оставаться включённым.
3. На остальных выберите найденную комнату либо введите её адрес, показанный в боковой панели создателя, и тот же код. Например: `192.168.1.10:39393`.
4. Текстовые каналы работают сразу. Войдите в голосовой канал или пригласите участника кнопкой около его имени. Приглашение требует подтверждения перед включением микрофона.
5. Кнопки звонка управляют микрофоном, звуком, камерой и демонстрацией. Для демонстрации выберите отдельное окно или экран; камера может работать одновременно.
6. Прикрепите файл кнопкой **+** около сообщения. Получатель самостоятельно выбирает место сохранения. Завершённая передача проверяется по SHA-256, максимальный размер файла — 2 ГиБ.

Настройки позволяют сменить имя, посмотреть адрес и выйти. История, каналы и отправленные файлы сохраняются на компьютере создателя комнаты между перезапусками. Имя и идентификатор клиента также сохраняются локально.

## Сеть и разрешения

Spark использует TCP **39393** для комнаты, UDP **39394** для обнаружения и динамические UDP-порты WebRTC для прямых звонков. Разрешите приложение в брандмауэре **частной сети** на обоих компьютерах. Если обнаружение блокируется, подключайтесь по IP; если включена изоляция Wi-Fi-клиентов/гостевая сеть, прямое соединение может быть недоступно. Перенаправление портов на роутере для одной сети не требуется.

На Wayland выбор окна/экрана проходит через системный портал, поэтому нужны работающие PipeWire и портал окружения (например, `xdg-desktop-portal-kde`). Камере и микрофону могут потребоваться системные разрешения. Передаётся изображение экрана и микрофон; захват системного звука в этой версии не реализован.

Используйте доверенную локальную сеть. Код ограничивает вход в комнату, но чат и файлы между клиентами и создателем передаются по HTTP/WebSocket без сквозного шифрования. Голос, камера и экран передаются напрямую через WebRTC с DTLS/SRTP. Нет STUN/TURN, облачного ретранслятора, телеметрии, автооткрытия полученных файлов или подключения к внешним сервисам. Приложение и установщик пока без цифровой подписи; Windows может показывать SmartScreen.

## Архитектура

- `spark-service`: Rust, Tokio/Axum, SQLite, обнаружение, сообщения и потоковые файлы. Каждый клиент запускает отдельный сервис на случайном порту `127.0.0.1`; создатель дополнительно слушает порт комнаты в LAN.
- `spark-protocol`: общий типизированный протокол Rust.
- `spark-ui`: интерфейс и логика WebRTC на Rust/Leptos, компилируются в WebAssembly.
- `desktop/`: тонкая оболочка Electron с одинаковым Chromium на Linux и Windows, изолированным renderer, системным сохранением файлов и выбором источника экрана. JavaScript здесь отвечает за интеграцию с рабочим столом; приложение не является полностью нативным Rust-виджетом.

## Сборка из исходников

Нужны Rust stable (не старее 1.88), Node.js **24+**, npm и системные библиотеки Electron. На Ubuntu 24.04: `libgtk-3-0 libnss3 libasound2t64 libgbm1 libxss1 libxtst6`. На Windows используйте Rust MSVC и Visual Studio Build Tools с C++.

```sh
rustup target add wasm32-unknown-unknown
cargo install wasm-bindgen-cli --version 0.2.130 --locked
npm ci
npm run build
npm start
```

`npm ci` скачивает закреплённую версию Electron. `npm run build` собирает обе Rust-части и WebAssembly bindings. Упаковка: `npm run package:linux` или `npm run package:win` на соответствующей системе. Готовые файлы появляются в `dist/`.

## Проверки

```sh
cargo test --locked -p spark-protocol -p spark-service
cargo check --locked -p spark-ui --target wasm32-unknown-unknown
# Linux: отдельный тестовый экран, реальные окна и два отдельных Rust-сервиса
npm run test:e2e:linux
```

Тесты используют настоящие TCP/WebSocket-соединения, SQLite и файлы. Сквозной сценарий запускает два независимых приложения, отправляет сообщения в обе стороны, создаёт канал, сверяет полученный файл с исходными байтами, проверяет реальную передачу RTP, декодирование кадров обеих камер, mute/deafen, приглашение, завершение и повторный звонок, перезапуск процессов с сохранением истории.

В Linux дополнительно захватывается настоящее тестовое окно на отдельном Xvfb-дисплее и проверяются пиксели принятого видео. Исходный рабочий стол пользователя не захватывается. Только в распакованной сборке явный флаг `SPARK_E2E_MEDIA=1` включает синтетические микрофон/камеру; в упакованной версии он игнорируется. Снимки и реальные WebRTC-счётчики сохраняются в `test-results/`. Windows CI проверяет сборку и сценарий с двумя клиентами; захват экрана Windows и оборудование разных физических компьютеров требуют отдельной проверки.
